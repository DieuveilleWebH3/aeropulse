# AeroPulse v0.1.0 — Fleet & Asset Management Foundation

AeroPulse `v0.1.0` is the first public milestone of the Predictive Maintenance & Aircraft
Fleet Health Monitoring Platform.

This release establishes the production-oriented Fleet and Asset Management foundation on
which the later telemetry and PHM capabilities will be built.

## Highlights

### Aircraft lifecycle

AeroPulse now supports registering, retrieving, listing, and retiring Aircraft.

Aircraft retirement is an explicit, idempotent lifecycle transition:

```text
ACTIVE -> RETIRED
```

The original `retired_at` timestamp is preserved across retries, and persistence uses a
conditional update to protect the transition under concurrent requests.

### Maintainable Equipment

Equipment can be registered against active Aircraft and retrieved individually or through
the parent Aircraft collection.

A physical Equipment item is identified by:

```text
(part_number, serial_number)
```

and that identity is unique across the Fleet.

Equipment registration and Aircraft retirement are serialized around the parent Aircraft,
preventing new Equipment from being attached after retirement.

### HTTP API

The first public Fleet API includes:

```text
POST /api/v1/aircraft
GET  /api/v1/aircraft
GET  /api/v1/aircraft/{aircraft_id}
POST /api/v1/aircraft/{aircraft_id}/retire

POST /api/v1/aircraft/{aircraft_id}/equipment
GET  /api/v1/equipment/{equipment_id}
GET  /api/v1/aircraft/{aircraft_id}/equipment
```

Business failures are exposed through stable error envelopes with explicit HTTP `404`,
`409`, and `422` semantics.

### Interactive API documentation

Start AeroPulse locally and open:

```text
Swagger UI   http://127.0.0.1:8000/docs
ReDoc        http://127.0.0.1:8000/redoc
OpenAPI JSON http://127.0.0.1:8000/openapi.json
```

The OpenAPI document includes project metadata, the MIT license, and separate Aircraft and
Equipment sections.

### Reliability and persistence

The release includes:

- async PostgreSQL persistence with SQLAlchemy;
- Alembic migrations through `20261101_0005`;
- PostgreSQL integrity constraints for lifecycle, uniqueness, and foreign keys;
- deterministic paginated reads;
- PostgreSQL + Redis readiness checks;
- transaction-scoped request handling;
- concurrency-safe Aircraft retirement and Equipment attachment behavior.

## Sprint 1 acceptance workflow

The release is validated end-to-end through:

```text
application readiness
    -> Aircraft registration
    -> Aircraft retrieval/listing
    -> Equipment registration
    -> Equipment retrieval/listing
    -> Aircraft retirement
    -> idempotent retirement retry
    -> existing Equipment remains readable
    -> new Equipment registration is blocked
```

Additional E2E scenarios validate fleet-wide Equipment identity and representative public
API failure contracts.

## What's next

The next phase moves beyond Fleet inventory into PHM capabilities, including telemetry
ingestion and the data foundation required for health scoring, anomaly detection,
degradation analysis, and remaining-useful-life estimation.

## Important safety statement

AeroPulse is an engineering demonstrator built with synthetic/public engineering data.

It does **not** claim certified aerospace prediction, airworthiness authority, flight-safety
authority, or maintenance-decision authority.
